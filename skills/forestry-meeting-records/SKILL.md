# 使用林地会议记录

以用户指定的林木权属证明为数据依据，使用内置 [Word 模板](assets/meeting-record-template.docx) 制作可填写、签字和盖章的会议记录底稿。模板采用简洁单页版式，不含项目数据；字段和版式详见 [会议记录规则](references/meeting-record-rules.md)。

## 来源与业务边界

- 先核对来源文件版本、项目、永久／临时性质、涉及单位和目标路径。按用户明确指定的证明提取工程名称、建设单位、地点、地块编号和面积，不自行转用调查表或旧版证明。来源冲突、缺项或一个会议涉及多个不同权利主体时，只暂停受影响记录并说明具体问题，不推测补齐。
- 林木所有权与林地所有权分别表述。本模板不增加土地权属结论，不把证明中的“林木集体所有”改写为“全部属于集体林地”。株数、蓄积不写入本模板。
- 工程名称、单位名称、地点和编号沿用来源；保持编号前导零、后缀、连接符及非连续关系，不重新编号或擅自扩大范围。面积以来源证明的公顷值为准，保留其精度；不重新汇总、舍入或换用其他面积。单位不明、来源缺失与明确零值分别处理。
- 永久与临时分别制作。村级使用村民代表大会格式，落款为该村村民委员会；林场单独制作会议记录，落款为林场。不得仅凭名称猜测主体性质；企业、个人、村民小组等其他主体先确认适用格式。
- 时间、会议地点、主持人、记录人、代表或会议人员总数、应到及实到人数留空。只保留日期中的“年、月、日”和手写空间，不预填村委会会议室、年份或人员信息。
- 正文预填讨论事项，随后直接接“参会人员签字”。不设置“表决结果”“会议决定”栏，不写“一致同意”、到会比例或“会议符合要求”，不复制签名、指印或印章。
- 签章采用“参会人员签字＋村委会盖章”或“参会人员签字＋林场盖章”。右下方保留单位名称、盖章提示和空白日期，不增加乡镇政府签章栏。

## 执行与文件组织

“先讨论”、检查或评审请求只读，不生成底稿或临时文件。用户授权制作或更新后，再执行以下流程；本 Skill 不扩大修改、安装或发布权限。

1. 只读提取来源，建立逐份记录与来源位置的对应关系；同时记录来源文件哈希。对接清单、提取结果、候选文档、备份及页面检查产物全部放系统临时目录或用户指定的仓库外目录，不写进通用 Skill 或正式成果。
2. 按“项目＋使用性质＋会议主体”组织。村级默认每个项目、每种使用性质一份合并 DOCX，各村分别独立起页；同名不同乡镇的村分别处理。林场默认每处一份独立 DOCX。来源已有的顺序优先，不把本次项目、地点或记录数量固化为通用配置。
3. 使用模板填写业务占位符，会议事实继续留空。模板是版式依据；使用现有文档工具或环境已具备的 OOXML／Word 能力编辑，不要求另行安装 Python 包。填充时保留段落、字体、留白及日期位置，不重建默认样式，不引入标题横线或主题色。
4. 默认保存为 `06_公示查验与报批/永久或临时/会议记录/会议记录（永久或临时）.docx`；林场为 `会议记录（林场全称）.docx`。路径中的项目根目录由用户明确指定或核实，不能从相似目录名猜测。用户指定文件名、拆分方式或模板时优先遵从。
5. 首次生成不覆盖已有文件。用户要求更新时，先比较现有文档；已手填的日期、人员、人数、签章及其他人工业务改动不能直接用模板覆盖。对未获授权的差异提出具体问题，不自动另存永久备份或增加成果文件。

## 核对与交付

- 逐份对照来源核对工程、建设单位、地点、使用性质、主体、编号和面积；验证来源未改。检查所有业务占位符均已填完，会议事实仍为空白，且没有下划线、表决栏、旧项目文字或测试数据。
- 每份会议记录默认一页，合并 DOCX 可包含多页。检查全部页面的标题、换行、人数填写空间、较大签字区和右下落款；人数与“人”不要分行，编号连接符两侧不要被添加空格。长标题或编号优先合理换行和调整间距；仍无法保持可读的一页时说明具体记录并确认续页，不靠缩小字体硬塞。
- 具备 Microsoft Word 时，使用独立实例只读重开候选、检查分页、导出 PDF 并逐页检查图像，完成后只关闭自建实例。其他环境使用已有且适用的文档渲染能力；不得强关用户的 Word、自动安装依赖或把未执行的检查说成通过。
- 确认候选通过核对和页面检查后，在原有授权范围内保存到目标路径。写入前重新比较来源及待更新文件哈希，变化即停止受影响文件；文件被占用时提示保存关闭，不强制解锁。
- 交付实际文件、记录数和页数、已完成的检查以及未完成事项。会议底稿仍需按实际会议填写和现场签章，不能将文档生成完成说成会议已召开或已达到报批条件。

## 安装与更新

完整复制本 Skill 文件夹，保留 `assets/`、`references/` 和 `agents/` 的相对路径。没有固定脚本入口或新增依赖；模板填充和渲染使用执行环境已有的文档工具。更新 Skill 只更新安装资源，不重建或覆盖项目内已经人工完善的会议记录。
