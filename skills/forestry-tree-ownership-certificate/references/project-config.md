# 项目配置与边界

一份 JSON 只处理一个项目、一种使用性质、一个工作表。用户只需提供完善后的调查表并要求制作，由 Agent 核对 `A.1`、制作内部配置，无需用户手填。真实配置和核对产物放系统临时目录。以下为虚构示例，不可当作真实项目资料；`true` 必须有用户确认或已核实材料支持。

```json
{
  "project_name": "某地 110 千伏输变电工程",
  "project_name_basis": "核准批复文件及页码",
  "applicant": "已核实的建设单位全称",
  "applicant_basis": "申请材料或委托材料的位置",
  "use_nature": "永久",
  "project_dir": "D:/某项目",
  "source": {
    "path": "D:/某项目/调查表.xlsx",
    "sheet": "A.1",
    "data_rows": [4, 5, 7],
    "columns": {"id": "A", "area": "H", "stock": "AD", "trees": "AE"},
    "area_basis": "占用面积，公顷，已核定",
    "stock_basis": "核定地块总蓄积，立方米，已核定",
    "trees_basis": "地块总株数，株，已核定",
    "confirmed": true
  },
  "groups": [
    {
      "city": "某市", "county": "某县", "township": "某镇", "village": "甲村",
      "owner": "甲村集体", "kind": "集体", "rows": [4, 5],
      "ownership_basis": "用户确认或登记材料的位置",
      "ownership_confirmed": true, "undisputed_confirmed": true,
      "trees_mode": "include",
      "note": ""
    },
    {
      "city": "某市", "county": "某县", "township": "", "village": "某林场",
      "owner": "某林场", "kind": "国有", "rows": [7],
      "ownership_basis": "已核实材料的位置",
      "ownership_confirmed": true, "undisputed_confirmed": true,
      "trees_mode": "omit", "trees_omit_basis": "本组缺少株数，用户确认省略",
      "note": ""
    }
  ]
}
```

## 映射和分组

- `source.sheet` 省略时默认 `A.1`；显式提供时必须非空，且只能来自用户指定工作表的授权。缺少默认表时报告可用表名并停止，不自动改读其他表。
- `columns` 指定 Excel 列字母，不猜中文字段。`data_rows` 是已核定的全部地块明细行，必须完整，不包含小计、合计。各组 `rows` 必须恰好覆盖一次，不能重复或遗漏。
- Agent 先检查 `A.1` 的实际表头，核对必需字段和单位后再映射；不得凭另一个项目的列位置照搬。不完整或不明确时报告缺项，不从其他表补齐；株数省略仍按下述授权规则处理。
- Excel COM 以只读、不更新链接、禁用宏的方式读取 XLS/XLSX；编号使用显示文本以保留前导零，数值取 `Value2`。编号列不能出现 `####`。合并单元格、公式错误和空编号／面积／蓄积停止；先人工确认并整理输入，不静默继承上下行。
- `area_basis`、`stock_basis`、`trees_basis` 是口径记录，不是脚本判定来源真实性的工具。`confirmed` 仅在字段、单位和范围核实后设置。每公顷指标不能填作总量列。
- 同一性质内重复编号停止；临时和永久独立运行，允许同号。跨市县同号但确为不同地块时先确定稳定唯一标识，不随意改写原编号。
- `kind` 首版仅支持已确认的“集体”“国有”。个人、共有或未明确的所有权先讨论扩展；不将其并入村集体。一个村有两个权利人可设两组。
- 集体必须有乡镇和村；国有林场可无乡镇，用实际林场名称填写 `village`。组顺序决定首页及正文顺序；同一行政区的多个组相邻排列，不能因按乡镇归集而合并权利人。
- `trees_mode` 每组明确为 `include` 或 `omit`。省略必须有 `trees_omit_basis`；不能推断缺失为零。所有包含株数的组都必须有总株数列及口径。
- `note` 是经核实、需要进入证明正文的特殊说明，不是模型的分析意见。无树／零蓄积地块可能需要不同证明文字，须确认后再用；不自动推断是否免办采伐许可。
- 脚本不能验证“无争议”法律事实；未确认不得设置 `undisputed_confirmed`。源表权属冲突须先解决，不能用配置掩盖。

## 数值和版式

面积逐组先求和，按 `ROUND_HALF_UP` 保留四位；原始蓄积逐组求和后按同规则取整数。不能先把每行蓄积取整后求和。不同组分别取整之和可能不等于全项目取整值，不为凑总量改某村数字。

默认 A4，页边距上／下 25.4 mm、左／右 31.75 mm；正文宋体 16 pt、首行缩进两字、行距 31.2 pt，标题 22 pt。对接备注正文 12 pt。签章区 14 pt，两栏无可见边框，签字／盖章／日期相邻排列，不隔开避免压章。年预留四字宽、月日各两字宽，不填实际日期。用户指定模板优先；首版脚本不导入任意外部模板。

## 更新和输出

默认目标为 `project_dir/06_公示查验与报批/使用性质/林木权属证明/林木权属证明（使用性质）.docx`。可以用命令参数 `--output` 指定同名 DOCX 的其他目录。不删除单村文件，不重新命名项目目录，不改工作簿。`--replace` 只是允许脚本暂存现有目标的更新，不能代替用户更新授权。

`project_dir` 可省略：仅当源表位于 `项目根目录/05_报告表格与图件/...` 时，脚本按该标准目录定位根目录；缺少或出现多个该层级时停止，要求 Agent 核实后显式填入。不会按工作簿父目录或当前工作目录猜测。使用性质仍由 Agent 核对后显式填写。批复工程名称另行核实，不从根目录名称推断。

例如临时源表位于 `D:/示例项目/05_报告表格与图件/表格/临时/调查表.xlsx` 时，最终文件为 `D:/示例项目/06_公示查验与报批/临时/林木权属证明/林木权属证明（临时）.docx`。所有预览、JSON 配置与核对文件只留在系统临时目录，发布仅复制最终 DOCX。

候选通过 Word 保存重开、验证正文完整性和表格数量后导出 PDF。自动核对输出的 `audit.json` 保存来源行、原始精度合计、报送数值和编号；这是内部核对产物，不附到正式 DOCX。脚本不提供只读审查模式；“先讨论”不运行它，不创建配置或暂存文件。
