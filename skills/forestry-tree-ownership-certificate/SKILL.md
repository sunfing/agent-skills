# 林木权属证明

默认交付每项目、每使用性质一份 `林木权属证明（永久）.docx` 或 `林木权属证明（临时）.docx`。首页为签章对接备注，各村集体／林场证明分别独立起页。现有单村文件不删除、不修改。脚本内置当前确认的无四至、左右两栏签章版式，不含真实项目数据。

## 只提供调查表时

用户提供完善后的小班因子调查表路径并要求制作证明，即可启动。默认检查该文件的 `A.1`，不能自行切换到 `内业处理表`、`附表A`、`附录A` 或其他同名近似表。只有用户明确指定其他工作表时才覆盖默认值。

- 由 Agent 读取 `A.1` 的实际表头、完整明细范围与计量单位，核对编号、占用面积、地块总蓄积、总株数及行政区划／权利人，建立内部配置；不要求用户手填 JSON、列字母或行号。已有核实的单位、权属和批准名称沿用。
- 缺少 `A.1`、必需字段缺失或含义不清时，说明具体工作表、字段及影响，停止生成；不能换表拼接、猜字段或把空值当作零。缺少株数仍须获得明确省略授权。
- 从源文件所在路径中的 `05_报告表格与图件` 定位其上一级项目根目录；无法唯一确定时再补充项目目录。永久／临时结合用户说明、路径及表内标题核对，存在冲突时询问，不把文件夹名称当作批复工程名称。
- 核对数据及全部页面后，将最终 DOCX 放入 `项目根目录/06_公示查验与报批/临时或永久/林木权属证明/`；配置、预览、核对信息和暂存文件只放系统临时目录。生成授权已包含此目录的最终保存，不另设重复确认。

## 先核定口径

先读 [项目配置与边界](references/project-config.md)，检查用户指定的原表、批复和模板。Windows、桌面 Microsoft Excel / Word、Python 3.10+；脚本仅用 Python 标准库，通过 PowerShell 调用 Office，不安装额外依赖。

- 工程名称以对应核准批复为依据，不能从目录名推定；申请／建设单位另行核实，不能将批复市级公司自动换成县级分公司。林勘单位不是业主，也不是当然的林木所有权人。
- 永久、临时分别使用用户指定的文件版本，工作表默认 `A.1`；Agent 核定数据行及编号列。同号不跨性质去重或合并。明确数据范围并排除小计、合计，不能按文件名日期自行选“最新版”。
- 面积必须确认是项目占用面积，单位公顷；不拿 TBMJ、XBMJ、Shape_Area 代替。蓄积必须是核定地块总量，单位立方米；调查蓄积与采伐设计蓄积分开。株数必须是地块总株数，不能用密度代替。
- 每份证明按行政区划和实际林木所有权人分组。同村多个权利人须拆分；林地权属代码不直接证明林木所有权。国有林场独立出证，不强归到乡镇下。
- 权利人、无争议结论须逐组确认。缺失不当作零，缺失株数仅在明确同意省略时去掉该项；无树、零蓄积、风倒木等特殊地块的写法须明确，不能自行作法律或采伐结论。
- 已核实信息沿用，不反复询问。遇实质冲突，列出来源和受影响组，停止该批生成；不得先生成带未经核实断言的正式证明。

## 默认文字和排版

- 开头用“因〔建设单位〕实施〔工程名称〕……”，由村／林场出具权属证明，避免“我单位（电力公司）出具证明”的主体混淆。日期、签字、印章均留空，不模拟签章。
- 面积汇总后显示四位小数；蓄积先按原始精度汇总，再用十进制四舍五入取整数；株数为非负整数。保留原始精度供核对。
- 纯数字编号排序，仅压缩不带前导零且真正连续的编号，范围用半角 `-`；非连续用顿号。带字母、前导零或后缀的编号原样保留，不擅自重编。
- 中文与西文／数字之间留空格，中文全角标点；编号 `-`、小数点保留。不要在全角括号内外任意加空格，不靠大量半角空格对齐。
- “特此证明。”与正文同字体、字号、首行缩进；无空段撑版，段落间距控制留白。签章区用无可见边框的两栏：左右均为“签字：、盖章单位：、日期”，两侧日期填写宽度一致，位置集中，允许印章覆盖签字和日期。
- 村集体左栏“村委会盖章：”，右栏“乡镇政府盖章：”；国有林场为“林场盖章：／主管单位盖章：”。本版不加入未确认的“意见”栏。
- 对接首页列项目名、性质、市县乡与村／林场，顺序与正文一致。先完成各村／林场签字盖章，再按项目收齐，按所属乡镇或主管单位归集集中办理；不是让各村自行同时办理乡镇盖章。注明“本页仅供签章对接使用，正式报送时不装入证明材料”。
- 上述为当前默认模板。当地另有明确要求或用户指定其他模板时，先对齐差异；不能用内置脚本无声覆盖当地要求，也不能声称支持任意 DOCX 模板保真合并。

## 生成与更新

Agent 为每个项目的永久／临时各建一份配置，放系统临时目录，不能将真实项目配置放进通用 Skill。核对表头后，源表映射精确到列和行；脚本不自动猜表头。`source.sheet` 省略时为 `A.1`，`project_dir` 省略时仅按上述标准源表目录结构定位项目根目录。

```powershell
python "<skill-root>/scripts/ownership_certificate.py" --config "<temp>/project.json"
```

默认仅生成临时候选 `candidate.docx`、Word 打印预览 `preview.pdf`、核对信息和 `stage.json`；不改源表或目标目录。已有目标会拒绝；仅在用户已授权更新该证明时加 `--replace`。更新会重新生成，不保留目标中的人工业务改动：先比较旧版与核定来源，确认需要保留的文字写入配置，不能盲目覆盖。原件及旧版备份只放临时目录。

逐份核对地块、权利人、面积、原始／报送蓄积、株数与来源行，检查重复、遗漏及总量；打开或渲染预览，检查所有页面、首页顺序、日期、两栏签章区和空白页。脚本的结构校验与 Word 重开不代替视觉检查。长证明可自然续页，不能为强行一页缩小正文或截断地块。

核对通过后，在现有用户授权范围内发布，无需重复索要已经给出的许可：

```powershell
python "<skill-root>/scripts/ownership_certificate.py" --publish-stage "<stage-dir>/stage.json"
```

发布再次校验源文件、配置、候选和原目标哈希；任一变化即停止。文件占用时报告，不强关 Office。交付只链接最终 DOCX，说明证明份数、实际核对、未解决事项；不得将自动生成或视觉检查通过称为法律确权或已满足报批条件。不自动安装到其他客户端、commit、push 或上传。
